# 01. Brand Art Direction

## Product Personality

QELL.AI is not positioned as a simple trading competition UI. The front end should express a deeper product narrative:

- Agentic trading infrastructure
- Modular Alpha Team composition
- Paper-runtime verification layer
- Live signal flow and team decision state
- Web3-native but not wallet-gimmick-driven

The product should feel like a command surface for agent teams, not a retail exchange terminal.

## Desired Feeling

When someone opens the product, they should feel:

- This is technical and serious.
- This is live and market-aware.
- This is not a generic DeFi dashboard.
- The core object is the Agent Team, not a candlestick chart.
- The interface has a game-like selection layer, but the runtime feels like trading infrastructure.

## Visual Keywords

Use these as design prompts:

- Dark terminal
- Agentic control plane
- Alpha infrastructure
- Modular trading team
- Signal routing
- Live simulation
- Circuit-like communication
- Sharp glass panels
- Technical leaderboard
- Black-box data source
- Execution gate

Avoid these:

- Generic SaaS dashboard
- Soft gradient hero
- Rounded marketing cards
- Exchange orderbook clone
- Overdecorated neon cyberpunk
- Crypto casino style
- Meme-token visual language

## Design Pillars

### 1. Agent-Native

The interface should make users feel they are managing a team of specialized agents. Runtime pages should show:

- Agent state
- Data source connection
- Signal transmission
- Team core / consensus
- Output or exposure state
- Session history

Charts can exist, but they should not dominate the product like a trading exchange.

### 2. Infrastructure, Not Campaign

The homepage can use Arena and leaderboard to attract users, but the broader UI should communicate that QELL.AI is a reusable system.

Preferred language:

- Runtime
- Signal Box
- Team Core
- Session Tape
- Exposure Field
- Position Lifecycle
- Market Sync
- Execution Gate

Less preferred language:

- Order page
- Buy / sell terminal
- Exchange panel
- Bot leaderboard only

### 3. Sharp And Dense, But Not Crowded

The product can be information-rich. The key is hierarchy:

- One dominant idea per panel.
- Big numbers only when they are the panel's main message.
- Do not let every module become a hero.
- Use micro-labels for metadata.
- Use short copy; avoid paragraph-heavy dashboard cards.

### 4. Controlled Color System

Use acid green as the primary QELL energy, cyan as system/info, violet as secondary intelligence, amber as execution/risk attention, and rose as catalyst/drawdown/negative state.

Do not flood large backgrounds with saturated color. Color should behave like a signal layer.

## Page-Level Style

### Homepage

Homepage should feel like an entry into the live Arena and QELL narrative:

- Dark fixed / animated technical background.
- Leaderboard appears early.
- Current pool and live paper competition are first-viewport signals.
- Brand nav remains disciplined and technical.

### Market / Builder

Market and Builder can feel more game-like:

- Agent cards can use rarity color.
- Particle identity can appear.
- Selection feels like MOBA hero picking.
- However, the system grid and panel language should still be technical.

### Runtime

Runtime is the most important product expression. It should not look like an exchange screen.

Runtime should communicate:

- Agents receive data.
- Agents process signals.
- Signals route to team core.
- Team core produces intent.
- Execution / exposure state updates.
- Session Tape records what happened.

## Visual Do / Don't

Do:

- Use thin borders and low opacity panels.
- Use uppercase micro-labels.
- Use subtle glow on active elements.
- Use circuit/beam lines to show communication.
- Use hover reveal for black-box data sources.
- Use role colors sparingly.
- Keep panel backgrounds dark and transparent enough to feel layered.

Don't:

- Use large saturated card backgrounds everywhere.
- Use huge action buttons inside data panels.
- Put repeated copies of the same team information in multiple places.
- Use exchange-like order table language unless the user is explicitly in an execution management view.
- Overuse green/purple gradients.
- Use rounded SaaS cards or blob backgrounds.

## Brand Voice In UI Copy

Good UI copy is compact and system-like:

- `Live Alpha Arena`
- `Agent Runtime`
- `Team Core`
- `Signal Box`
- `Session Tape`
- `Exposure Field`
- `Markets Synced`
- `Execution Gate`
- `Position Lifecycle`

Avoid tutorial copy inside the UI. Explanatory text should be short and contextual.
