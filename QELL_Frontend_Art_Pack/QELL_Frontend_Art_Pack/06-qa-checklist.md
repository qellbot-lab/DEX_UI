# 06. Visual QA Checklist

Use this checklist before presenting a page as QELL-aligned.

## Brand Alignment

- [ ] Page feels dark, technical, live, and infrastructure-like.
- [ ] Page does not look like generic SaaS.
- [ ] Page does not look like a retail exchange terminal unless explicitly intended.
- [ ] Accent colors are semantic, not decorative.
- [ ] No purple/green color wash over the whole UI.

## Typography

- [ ] Chakra Petch is used for product UI.
- [ ] Merkur is only used for brand mark / major brand moment.
- [ ] Micro-labels are uppercase with letter spacing.
- [ ] Headings fit containers.
- [ ] No text overlap.
- [ ] No clipped long words in buttons/cards.

## Color

- [ ] `--bg`, `--surface`, `--line`, `--text`, `--muted`, `--faint` are used consistently.
- [ ] Acid green is reserved for primary action/live signal.
- [ ] Cyan is used for system/data.
- [ ] Violet is used for secondary intelligence/quant.
- [ ] Amber is used for execution/caution.
- [ ] Rose is used for catalyst/negative/drawdown.
- [ ] Rarity colors do not bleed into unrelated product pages.

## Layout

- [ ] Top navigation does not shift between routes.
- [ ] Panels have clear hierarchy.
- [ ] No giant empty areas without intentional visual purpose.
- [ ] No crowded panels with too many competing metrics.
- [ ] Repeated information is removed.
- [ ] Components are not nested cards inside cards unless necessary.

## Runtime

- [ ] Runtime feels agent-native, not exchange-native.
- [ ] Agents have clear boundaries.
- [ ] Agents are arranged around the Team Core naturally.
- [ ] Connection lines sit behind agents.
- [ ] Data source boxes are understandable by default and reveal detail on hover.
- [ ] Session Tape has UTC date/time.
- [ ] Exposure Field does not look like an exchange order table.

## Marketplace / Builder

- [ ] Agent Marketplace cards are scannable.
- [ ] Hover preview is readable and not clipped.
- [ ] Rarity color is visible but not overwhelming.
- [ ] Builder feels like team composition, not a standard form.
- [ ] Team configuration can be understood before final compile.

## Motion

- [ ] Motion is smooth and continuous.
- [ ] No stuttering line effects.
- [ ] No hard color blinking.
- [ ] Breathing lights use opacity/brightness, not color switching.
- [ ] Always-on animations are limited.
- [ ] Page remains responsive while animations run.

## Responsive

- [ ] Desktop wide viewport has no stretched or broken panels.
- [ ] Laptop viewport remains readable.
- [ ] Mobile/narrow viewport stacks gracefully.
- [ ] No horizontal overflow.
- [ ] Fixed nav does not cover first content.

## Accessibility And Usability

- [ ] Text contrast is readable.
- [ ] Buttons have clear focus/hover states.
- [ ] Critical actions are not hidden behind hover-only UI.
- [ ] Close/Pause/Adjust actions are discoverable.
- [ ] UI terms match product concepts.

## Final Product Taste Check

Ask:

- Does this feel like QELL.AI?
- Does this feel like agentic trading infrastructure?
- Does this page teach the user what matters without over-explaining?
- Would a Web3 VC or product lead understand that this has a unique product language?
