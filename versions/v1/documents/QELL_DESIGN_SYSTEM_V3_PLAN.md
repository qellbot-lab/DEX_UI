# QELL 中文版视觉系统 V3 设计方案（待确认）

## 0. 结论

上一轮失败的根本原因不是“绿色不对”或“信息还不够少”，而是没有先建立设计系统，直接把一组视觉关键词交给图片模型。最终页面出现了典型生成式 UI 痕迹：每个模块都被卡片化、每个指标都配图标、粒子人像重复出现、雷达图和六边形泛滥、状态色承担装饰、线框缺少真实组件逻辑。

V3 不再从“画一张看起来像 QELL 的图”开始，而从可实施、可复用、可验收的产品设计系统开始。最终预览图应由真实 HTML/CSS 页面截图产生；ImageGen 只允许生成局部 Agent 身份资产，不再生成完整 UI。

## 1. 资料分析

### 1.1 Art Pack 的有效价值

`QELL_Frontend_Art_Pack` 中真正值得继承的是：

- 深色基础设施语境，而不是普通 SaaS 或交易所后台。
- 固定且稳定的全局导航。
- 由排版、间距和数据层级主导的页面，而不是大面积装饰。
- Acid 绿色用于主要动作和 Live 状态，Cyan 用于数据，Ember 用于执行，Rose 用于风险。
- Runtime 的核心对象是 Agent、Team Core、Session、Exposure，而不是 K 线。
- 一个面板只表达一个核心结论；短文案、渐进披露。
- 动效表达状态变化，不作为背景噪声。

### 1.2 Art Pack 中必须覆盖或修订的内容

- 文档原有 Violet / Violet Strong / Violet Soft 与用户最新要求冲突，V3 全部删除。
- 原 CSS 大量使用 `rgba`、渐变和 `backdrop-filter`。V3 改为明确的实体表面层级，减少玻璃感。
- 原 Runtime 建议的 circuit/beam line 只能在关系确实重要时使用，不可成为页面装饰。
- 原“thin border”调整为清晰的 1 CSS px 实线，并严格贴合像素网格；禁用 0.5px、断裂、草图式或随机线路。
- Chakra Petch 不适合承担全部中文正文。它只负责英文标签、数字与少量界面标题，中文需要独立可读字体体系。

### 1.3 Eryx 版本 1 与版本 2

版本 2 比版本 1 的信息分组、留白和主次关系更清楚，可以作为内容布局参考；但两版都存在以下问题：

- 粒子人像成为几乎每个页面的默认主视觉。
- 圆环、六边形、雷达图和轨道图被当作“高级感”的快捷方式。
- 绿色高亮面积过大，Live、CTA、指标、边框、图标同时发亮。
- 全部内容都被装进同样重量的卡片，缺少无框区域和真正的页面节奏。
- 图表经常是装饰性数据，没有明确的轴、基准、时间范围或操作意义。
- 连接线数量过多，复盘页和战队页尤其像概念信息图，而不像可操作产品。
- 中英文层级混杂，数字、标签和中文标题没有建立稳定的排版关系。

因此 Eryx 仅用于识别产品对象与局部构图，不作为最终视觉模板。

## 2. Design Context（草案）

### 用户

桌面端为主的中文 Agent 交易产品用户。他们需要发现智能体、组建战队、选择历史事件、观察模拟、理解决策并复盘结果。使用情境偏专注、分析和验证，而不是休闲浏览。

### 品牌人格

三个关键词：**克制、精确、有后果感**。

- 克制：状态色稀少，特效服从内容。
- 精确：数据、对齐、术语和交互状态都有明确规则。
- 有后果感：交易动作、风险和模拟结果看起来真实且值得认真判断。

### 视觉方向

方向名：**Quiet Trading Infrastructure / 静默交易基础设施**。

它不是 Jarvis 科幻 HUD，不是 Web3 Casino，也不是传统券商终端。它应接近一套高端、编辑式的 Agent 操作系统：大标题和真实数据形成视觉重心，表面层级安静，只有正在发生的状态才获得颜色与动效。

### 反目标

- 不做黑客终端、赛博 HUD、霓虹游戏菜单。
- 不用紫色、蓝紫渐变或紫绿对撞。
- 不把每个内容块都做成卡片。
- 不用六边形、圆环评分、雷达图作为通用组件。
- 不用无意义 Sparkline、随机粒子和装饰连接线制造“专业感”。
- 不使用图片模型直接生成整页 UI。

## 3. 设计原则

### 原则 A：排版先于图形

页面首先通过标题、数字、行距、列宽和留白建立高级感。图标和插画不能承担结构职责。

### 原则 B：颜色是动词

- Acid：可操作、已激活、正在运行、正收益。
- Cyan：数据、同步、系统信息。
- Ember：执行中、需注意、尚未完成。
- Rose：损失、冲突、风险、失败。
- Neutral/Steel：Quant、智能计算和普通信息；不再为 Quant 新增紫色。

### 原则 C：无框优先，面板按需

先用空间、对齐和分隔建立分组；只有可操作、可选择、需要独立状态或需要明确边界的内容才使用完整边框。

### 原则 D：一屏一个主要判断

每个 16:9 视口必须回答一个核心问题。一个视口最多：

- 1 个主视觉或主图表；
- 1 个主操作；
- 3 个次级数据组；
- 5 个以内的主要强调色对象。

### 原则 E：效果必须可解释

粒子、连线、光晕和动画只有在表达 Agent 身份、连接或 Live 状态时才能出现。无法解释其产品含义的效果一律删除。

## 4. Foundations

### 4.1 色彩系统

V3 采用 Primitive 与 Semantic 两层 Token。

#### 中性表面

| Semantic Token | 建议值 | 用途 |
| --- | --- | --- |
| `canvas` | `#050706` | 页面基底 |
| `surface-1` | `#0a0d0b` | 普通内容层 |
| `surface-2` | `#101411` | 浮层、选择态背景 |
| `surface-3` | `#171c18` | Popover、关键悬浮内容 |
| `border-subtle` | `#252c27` | 普通分隔 |
| `border-strong` | `#3b453d` | 输入、选择、交互边界 |
| `text-primary` | `#f2f5ec` | 标题、关键数据 |
| `text-secondary` | `#a8b0a8` | 正文、说明 |
| `text-tertiary` | `#69716b` | 元数据、禁用状态 |

#### 状态色

| Semantic Token | 值 | 使用限制 |
| --- | --- | --- |
| `action-primary` | `#b7ee5b` | 主 CTA、Active、Live；单屏视觉重量不超过约 8% |
| `data-info` | `#6de3d3` | 同步、系统数据、结构信息 |
| `status-warning` | `#eab56c` | 执行、等待、风险注意 |
| `status-negative` | `#e6789e` | 损失、失败、冲突 |
| `intelligence-neutral` | `#b8c2ba` | Quant、模型、智能计算 |

不再定义 Purple、Violet、Magenta、Indigo、Lavender、Lilac 或 Mauve Token。

#### 配色比例

- 60%：Canvas 与大面积暗场。
- 30%：中性表面、文字和边界。
- 10% 以下：全部状态色总和。

### 4.2 字体系统

#### 字体职责

- Logo：Merkur，仅使用现有 Logo 资产，不用于正文。
- 英文标签、数字、短标题：Chakra Petch Medium / SemiBold。
- 中文标题和正文：优先采用已授权的现代中文无衬线字体；原型阶段使用系统中文字体栈，生产前确定并本地化字体文件。

#### 固定产品字号

| Token | 尺寸 | 用途 |
| --- | --- | --- |
| `label-xs` | 12px / 16px | 英文微标签、时间、状态 |
| `body-sm` | 14px / 22px | 元数据、辅助说明 |
| `body-md` | 16px / 26px | 中文正文 |
| `title-sm` | 20px / 28px | 面板标题 |
| `title-md` | 28px / 36px | 页面分区标题 |
| `title-lg` | 48px / 52px | 产品页主标题 |
| `metric-md` | 32px / 36px | 主要面板数据 |
| `metric-lg` | 48px / 48px | 单屏核心数据 |

- 数据全部使用 tabular numbers。
- 中文不做大字距全大写效果。
- 每屏最多 5 个字号层级。

### 4.3 空间与网格

- 设计基准：1440px 宽桌面视口；内容最大宽度 1320px。
- 12 列网格；24px gutter；左右安全边距 40–60px。
- 4pt 基础空间：4、8、12、16、24、32、48、64、96。
- 导航高度 72px；页面首段距导航 64px；大分区间距 96px。
- 主内容通常占 7–8 列，辅助内容占 3–4 列，至少保留 1 列呼吸空间。
- 内容密集页使用纵向滚动，不为了“单张海报完整”压缩真实网页布局。

### 4.4 边界与表面

- 默认圆角 0；仅原生输入控件或极小状态点允许 2px。
- 边框只允许 1 CSS px 实线，并贴合整数坐标。
- 不使用 0.5px、不透明度过低的毛刺线、随机缺口或装饰边角。
- 不使用通用玻璃拟态；默认不使用 `backdrop-filter`。
- 暗色主题通过表面亮度层级建立深度，不使用明显阴影。

## 5. 组件架构

### 5.1 表面层级

1. **Canvas Region**：无框，承担标题、主图表和大面积内容。
2. **Section Group**：只使用上下分隔或背景差，不使用完整卡片。
3. **Interactive Panel**：可点击、可选择、拥有独立状态时使用完整边框。
4. **Focus Surface**：Popover、详情或当前选择；使用更亮实体表面，不用发光边框。

### 5.2 核心组件

- `GlobalNav`：固定高度、固定 Logo 尺寸、路由切换不位移。
- `PageIntro`：Eyebrow、标题、最多一行说明、可选右侧主状态。
- `MetricStrip`：2–4 个指标，数字优先，不为每项配大图标。
- `SectionHeader`：标题、辅助状态、可选文本动作。
- `PrimaryButton / SecondaryButton / DestructiveButton`：明确八种交互状态。
- `SegmentedControl`：用于模式选择；不使用 Pill 外观。
- `StatusLabel`：文字 + 小型几何标记，不能只依赖颜色。
- `DataTable`：真实列对齐、Tabular numbers、Hover/Selected 状态。
- `AgentIdentity`：粒子形象只在 Agent 身份焦点出现；列表中使用静态缩略图或字母标记。
- `AgentRow / TeamSlot`：结构化信息优先，不复制整张人物卡。
- `ChartFrame`：包含标题、时间范围、轴、基准、Legend 和空状态。
- `TimelineBlock`：事件用实体块表达；只有连续时间关系明确时使用连接轨。
- `SessionRow`：时间、动作、参与 Agent、结果与详情入口。
- `ExposureRow`：市场、方向、状态、PnL、轻量操作。

### 5.3 明确删除的通用模式

- Icon + 六边形 + 标题 + 一行文案的重复卡片。
- 三个圆环评分并排。
- 每页一个雷达图。
- 粒子头像出现在所有列表与所有模块。
- 无轴、无时间范围的装饰 Sparkline。
- 卡片嵌套卡片。
- 用边缘发光代替选择状态。
- 作为背景装饰的细电路线、十字准星和随机刻度。

## 6. 数据可视化规范

- 每张图必须有明确问题：趋势、对比、构成、阶段或关系。
- 趋势图必须显示时间范围和基准；风险图必须显示阈值。
- 主数据系列用 Acid；比较系列用 Steel；系统参考用 Cyan。
- Rose 只用于负值或风险，不用于装饰。
- 图表网格线使用少量水平线；默认不显示完整棋盘格。
- 一个视口最多一张复杂可视化。
- Radar 仅在“多维能力对比”确实是核心任务时使用，不能作为详情页默认装饰。

## 7. 动效与交互

- 100–150ms：按钮按下、颜色与边框反馈。
- 200–300ms：Popover、选择态、Hover reveal。
- 300–500ms：Drawer、分区切换。
- 仅动画 `transform` 与 `opacity`。
- 页面只允许一个持续 Live 动效；其余状态静止。
- 粒子 Agent 默认静态，聚焦或加载时才发生局部运动。
- 所有 Hover 必须有 Focus 对应状态。
- 支持 `prefers-reduced-motion`。

## 8. 页面级信息架构

以下“屏”指同一网页的连续滚动分区，不是独立海报。

### 首页：3 个滚动分区

1. 产品入口：主张、主要 CTA、Live proof；不同时展示三张巨大 Agent 卡。
2. Agent 与流程：三位代表 Agent + 六步流程，使用无框编辑式布局。
3. 历史事件、排行榜与奖励预览：分成上下两段，不在同一行竞争。

### 选择角色页：2 个分区

1. Agent 市场：可扫描列表或紧凑网格，筛选与当前战队固定。
2. 选中 Agent：单一大身份视图 + 兼容性 + 加入操作。

### 组建战队页：2 个分区

1. 编组工作区：Team Core、槽位、当前选择和战队意图。
2. 模拟前校验：适配、冲突、贡献和开始模拟。

### 智能体详情页：2 个分区

1. 身份与可验证表现：粒子身份只出现一次。
2. Strategy DNA：用证据、因子、市场环境和历史行为，不默认使用雷达图。

### 历史事件副本页：2 个状态

1. 事件库：事件列表为主，图表缩略图极简。
2. 事件详情：主图表、学习目标、适配战队和进入模拟。

### 模拟盘直播页：2 个纵向区域

1. Runtime 总览：Agent 状态、Team Core、关键市场上下文；K 线为辅助。
2. 决策 Dock：Session、因子调用、Subagent、仓位与压缩事件流。

### 排行榜页：2 个分区

1. 排名：主榜 + 当前用户位置。
2. 奖励与资料：等级进度、近期模拟、奖励预览。

### 副本结算页：2 个分区

1. 结果总览：收益曲线、核心结果和结算动作。
2. 复盘：贡献、最佳/最差决策、关键事件和下一步。

## 9. 分阶段执行方法

### Phase 0：确认设计上下文

确认用户对象、桌面优先级、粒子资产保留程度和中文字体策略。确认后写入 `.impeccable.md`，成为后续所有页面的约束。

### Phase 1：Foundations

输出：

- `qell-v3-tokens.css`
- `qell-v3-tokens.json`
- 字体层级样张
- 色彩与对比度样张
- 12 列网格和空间样张

验收后才进入组件。

### Phase 2：Component Lab

用真实 HTML/CSS 建立组件试验页，覆盖默认、Hover、Focus、Active、Disabled、Loading、Error、Success 八种状态。

首批组件：导航、按钮、状态、指标、表格、Panel、Agent Row、Team Slot、Chart Frame、Session Row、Exposure Row。

### Phase 3：双页面 Pilot

建议同时验证两个极端：

- 首页第一段：验证品牌、留白和高级感。
- 模拟盘 Runtime 第一段：验证数据密度、Agent-native 表达和真实产品可用性。

两页均以 HTML 浏览器截图验收，不用图片模型生成整页。

### Phase 4：页面模板

先完成 Agent 市场、Team Builder、事件库三个高复用模板，再扩展到详情、排行榜和结算。

### Phase 5：局部资产

只有设计系统和页面结构通过后，才生成少量粒子 Agent 身份图。每种角色只生成可复用的透明资产，不在图片模型中混入 UI 文本和组件。

### Phase 6：视觉 QA

- WCAG AA 对比度。
- 紫色家族像素检测为 0。
- 单屏状态色视觉重量低于约 10%。
- 单屏最多一个粒子主视觉、一个复杂图表、一个持续动画。
- 无卡片嵌套，无装饰 Sparkline，无随机细线路径。
- 导航尺寸、标题基线、按钮高度跨页面一致。
- 1440px、1280px 和窄桌面视口均无溢出。

## 10. 下一步建议

不要继续一次性生成 18 张图。下一步只做 **Phase 1：Foundations + Component Lab 的第一版 HTML**，再制作首页首屏与 Runtime 首屏两个真实网页 Pilot。两者通过后，再批量迁移其他页面。

## 11. 待确认问题

1. 是否确认 V3 的方向为“静默交易基础设施”：克制、精确、有后果感？
2. 是否同意粒子 Agent 只作为身份资产，每个视口最多出现一次，而不再作为所有卡片缩略图？
3. 第一阶段是否只做桌面端 1440px，并在体系稳定后再做移动端？
4. 中文字体在原型阶段是否允许先使用系统字体栈，生产前再确定并引入已授权字体？
