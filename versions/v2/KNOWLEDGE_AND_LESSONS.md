# V2 Task Nodes, Knowledge, and Lessons

## Execution Nodes

1. **Freeze the past** — V1 was copied, hashed, counted, and documented before V2 work began.
2. **Separate authorities** — the purple Chinese drafts control content; the reference site controls visual language; neither is allowed to silently control both.
3. **Capture before interpretation** — stable reference screenshots at 1440 × 900 were measured before choosing a system.
4. **Name the visual thesis** — “Institutional Alpha Studio” replaced the vague goal of “more advanced”.
5. **Define hierarchy levels** — open stage, editorial band, work surface, instrument inset, active object.
6. **Plan the journey** — eight routes and their primary actions were mapped before implementation.
7. **Choose a character system** — institutional typographic identity plates replaced people, particles, and role geometry.
8. **Build one connected prototype** — page state persists across selection, team, event, runtime, result, and ranking.
9. **Audit visually** — reference and prototype screenshots were judged together at the same viewport.
10. **Audit as a product** — competitor patterns were used to clarify simulation, team roles, human control, and attribution.
11. **Audit technically** — mobile, desktop, semantics, touch, performance, console, dependencies, and forbidden colors were verified.
12. **Package evidence** — design brief, tokens, specs, audits, screenshots, and run instructions ship with the code.

## Durable Design Lessons

### Hierarchy is not 3D

Depth comes from different responsibilities having different scale, spacing, density, contrast, and shadow behavior. Adding perspective or more glow would not have solved V1's sameness.

### A design system should unify behavior, not force one layout

V1 looked repetitive because it treated the same framed panel as the answer to every information problem. V2 reuses tokens and primitives while giving each route a task-specific composition.

### Low density requires stronger focal decisions

Whitespace feels premium only when the remaining content is decisive. Every viewport therefore needs one headline, one primary action, and at most one complex evidence surface.

### Character identity can be typographic

Trading strategy Agents do not need portraits or abstract avatars. Codes, names, registration lines, evidence, and risk signatures can produce a more credible institutional identity.

### Color is strongest when it behaves like a verb

Acid means active or positive; cyan means data or structure; ember means execution or caution; rose means risk or negative. Neutral steel replaces purple as the quantitative layer.

### Explainability is not chain-of-thought theater

The useful product record is input factor → called subagent → action → confidence → state change → outcome. It is more trustworthy and actionable than fabricated internal monologue.

### Long pages are a density tool

The page should be scrollable when one decision naturally leads to another. “One page” does not mean “one 16:9 poster”. Chapters create rhythm without fragmenting the route.

### Reference fidelity still requires editorial judgment

The reference site's scale, material, restraint, and hard edges are valuable. Its purple residue, particle noise, overly faint detail, and English-first density were intentionally removed for this Chinese product.

## Engineering Lessons

- Real route state exposes flow problems that static images hide.
- Route-level lazy loading reduced the initial monolithic build and removed the chunk warning.
- Deterministic charts are better for visual QA than implicit animation.
- Accessible primitives help, but custom interactive surfaces still require roles, states, labels, and keyboard behavior.
- A final forbidden-token scan is a cheap and reliable guard against color-system regression.
- Version compatibility matters: Vite 6.4.3 supports the local Node runtime and removes the vulnerabilities found in 6.2.6.
